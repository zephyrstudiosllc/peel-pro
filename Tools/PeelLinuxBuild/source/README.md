This isolated native encoder delta is **not yet compiled or an accepted Linux release**. Its exact predecessor published at e0f64f7ca3b64a2c436ec1e9ad5c3b6285cf4eed passed the first hosted Debian13 x86_64 build and nine pure codec checks; that result does not cover this new source. Parent release work `w-0ff050f9cbfe4afbba828c06a3ebfed0` remains open. Current encoder worker `w-16cb3a8d65bb49f99b917e7e8330a42e`; original application source worker `w-613348446ab84fd2b7a81d5ab9dbb889`.

## What is implemented

- `native/` is a real C11/GTK4 application and shared media/credential library. **Computers** is one interface with an explicit **Linux** label and Mac/Windows/Linux remote copy. Source selection goes through libportal, obtains only the granted PipeWire remote FD and uses the actual `pipewiresrc` plugin. It prefers v6 `pipewire-serial`/target-object, disables reconnect, and retains legacy node IDs only inside the current restricted live session. Each Start gets a fresh epoch. Source close, portal revoke, timeout, Stop and main-window close fence old callbacks and tear down capture. No restore token is persisted.
- Actual capture frames go through GStreamer conversion to mapped BGRA, bounded dimensions/area, checked row stride and an owned one-latest-frame mailbox. GTK updates happen on its main loop. Popouts preserve content aspect and choose their initial dimensions from the real stream. Frames are never written to disk. The changing frame count in the popout title comes from real appsink samples.
- `managed/` composes the existing portable **ClientSession**, **ClientVideoSocketSession**, **ClientStreamController**, protocol packet reader and **BouncyCastle TLS-PSK** transport. Upstream client namespaces are retained to minimize copying changes. Only two inherited text constants say Linux instead of Windows. Exact base hashes are in `BASE-SHA256.json`.
- The receiver opens a current authenticated window from the actual host list, opens the existing per-window TLS video channel and sends normal startStream. H264 SPS/PPS and AVCC access units are validated/converted to Annex B at the codec boundary, then sent to real GStreamer h264parse/avdec_h264/appsink. The native decoder renders real samples. It never reports a fake decoded frame from a successful enqueue. HEVC is not advertised. Native rows and close callbacks carry the actual session generation; queued old rows/popout callbacks cannot select a replacement account/host window. Disconnect and stream close cancel current transport resources.
- Pairing uses the existing six-digit PIN TLS identity, HKDF/HMAC proof and PairRequest/PairResponse, through a local interactive terminal command. The PIN is read without echo; it is never accepted from argv/env or logged. Long-term PSKs are stored only in Secret Service via libsecret, bound to exact stable host ID. Locked/unavailable/corrupt stores fail closed. There is no plaintext trust/network fallback or PSK file.
- Packaging includes a Linux-only CMake build, .NET 10 executable, launcher and desktop entry named **Peel Pro**. No install step runs automatically.

## Opt-in native outgoing encoder seam (source-only delta)

`peel_linux_host_observe` reports actual portal source generation/opaque source1/current BGRA dimensions; source inactive is delivered synchronously on Stop/revoke. The main-context-only encoder start API requires that exact active generation and actual factories. It retains exactly one actual raw sample<=128MiB and seeds it on exact current Start, so a static source needs no later damage to deliver its first frame. Caps/generation are rechecked at seed admission; close/reselection releases the retained sample. A one-buffer leaky appsrc feeds the fixed real OpenH264 encoder directly into explicit byte-stream/AU/constrained-baseline caps and the strict Annex-B/IDR/parameter/timestamp validator, then a two-AU/8MiB queue counting AVCC+SPS+PPS. The outgoing pipeline omits redundant h264parse because its repeated-PTS suppression discards the actual timestamp on explicit static replay; the receiver pipeline still requires h264parse. Explicit keyframe replay preserves actual sample PTS; a strict-increasing managed consumer needs a new encoder epoch for static recovery, and must not immediately request a duplicate seed after Start. Borrowed callback bytes carry source/encoder/config generations, actual dimensions/ns timestamps, SPS/PPS and four-byte AVCC NAL lengths. Backpressure/overflow suppress dependent output until fresh IDR; no sink/failure callbacks follow exact Stop. This does not grant network or input authority. See native/include/peel_linux.h for the precise callback contract.

A prepared CTest source exercises Annex-B conversion, exact full-item8MiB cost boundaries, static first-sample-before-attachment with no later damage, explicit same-PTS native keyframe replay, rejected delivery/recovery, stale generation, a new-size/pending-publication race, retained-sample release and revoke with queued output. It requires the actual openh264enc factory, runs without GTK initialization/display/portal/socket, and has a finite20s timeout. It has NOT been built/run for this delta. The proposed CI runner adds only this bounded native test invocation after the existing build; root owns reviewed publication and one execution.

## Remote Desktop UX regrouping (source-only delta, 2026-10-21)

The main window is now **Remote Desktop** with two GTK stack tabs. **Connect** holds the existing saved-pairing form (labelled Computer ID, Address, Streaming port), Connect/Disconnect, receiver status, the current authenticated window list (with an empty-state line) and a collapsed terminal pairing guide that repeats the `--pair` route above. **Share This Computer** holds Choose source, the registered host row (Pair a device, Share selected source, Stop sharing) with tooltips that name each availability condition, and its own status line. Portal/capture messages from `media.c` now go to the Share status (`peel_share_status`); receiver and decoder messages stay on Connect. A receiver viewer is titled after its exact current row (session generation plus window ID, looked up on the GTK main loop), otherwise the previous generic title. Capability copy matches the code: viewing only, one stream at a time, opening another window replaces the viewer, closing the viewer stops it; host input/clipboard is refused and audio is not shared.

## Receiver source audio playback and source media controls (source-only delta, Peel248, 2026-10-23)

Receiving side only; the Linux host stays view-only and advertises no audio, media or volume capability. Frozen contract: root `source-media-contract.md` (source media v1).

- **Playback.** `managed/Receiver/LinuxReceiverAudio.cs` is the one playback owner per control generation: `audioSessionRequest` (mode `playback` only), challenge plus HMAC proof (`AudioPairingProof`, PSK zeroed after use), a ticket into an auxiliary TLS-PSK `audioStreamHello` on the saved endpoint, then the mirrored bounded PEAU v1 reader (format first, 20 ms S16LE/48 kHz stereo, ≤4096-byte payloads). Sequence or sample-time regression drains and recreates the sink, with at most 8 resets. Voice and the microphone are never requested. Ticket and key bytes never reach status text or logs. The client advertises `mac-system-audio-v1` only when `peel_linux_audio_available()` found the factories AND autoaudiosink reached READY on a real audio sink at Connect. Its fakesink no-usable-sink fallback counts as no output, both in that probe and in each playback pipeline.
- **Native sink.** `native/src/audio.c`: appsrc → audioconvert → audioresample → autoaudiosink, live/do-timestamp with 40 ms min latency. Each push is exactly one 3840-byte packet; at most 200 ms is queued and further packets are dropped, never blocked. A bus sync handler latches ERROR/EOS, then unrefs and drops every message. There is no GTK and no default-context watch. The receiver generation fences push. The ABI is in `peel_linux.h`.
- **Default Listen.** `managed/Receiver/LinuxReceiverControls.cs` starts playback once the first access unit of the current stream is admitted to the native decoder. It needs the backend ready, the source advertising audio and no explicit Off for that pairing. Listen Off persists per pairing as a domain-separated SHA-256 in `~/.local/share/PeelPro/Receiver/preferences.json`, and Listen On clears it. Closing the last stream, Disconnect, an error, a stale generation or a source `stopped`/`unavailable` state stops playback without writing Off. An unreadable preferences file suppresses automatic Listen until the user makes an explicit choice. The existing client always reports itself visible, so there is no background trigger.
- **Source controls.** The viewer toolbar (`native/src/viewer_controls.c`) has Listen, source mute plus a volume popover, and source previous/play-pause/next. Callbacks carry the viewer's exact window and receiver generation. `managed/Receiver/LinuxSourceMedia.cs` sends `sourceMediaCommand`/`sourceVolumeQuery`/`sourceVolumeSet` only on the captured control generation and pairing, for the current stream window. It allows ≤8 pending requests with a 3 s timeout. Replies must match the request, pairing, window and generation; late or older-sequence states are ignored. Volume sets are latest-coalesced with one in flight and are never optimistic. Media buttons are enabled only when the source advertises `source-media-keys-v1`. Every admitted stream gets a new epoch, even when the same window ID reopens. The GTK callback captures that window+epoch before queuing into one bounded (32) serialized queue, and the command acts only if that exact binding is still current. Ending or replacing a stream cancels its sends while they wait for the `ClientSession` writer, and an owner check runs again at write time. One volume set is in flight, owned by its requestId and epoch, and only that owner can release the slot or pump the next value.
- **Volume scope.** `LinuxSourceVolumeScope.Selected` is `systemOutput`, following root's stated default in `volume-implementation-choice.md`: the source computer's actual output volume and mute. Listen stays separate. Volume and mute are enabled only when the source also advertises `source-volume-v1`; otherwise they stay disabled and send nothing. There is no receiver-volume or other-scope fallback. Setting the adapter to null turns source volume off with no other change.
- **Visibility settings.** Connect → Viewer controls holds `peel.controls.showVolume` and `peel.controls.showMediaControls`, both default true. They are presentation only.
- **Wire protocol.** `vendor/Peel.Windows.Protocol/{AudioMessages,AudioPackets,MachineStatusMessages,SourceMediaMessages}.cs` are exact byte mirrors of the current, still-unsealed Windows working-tree files. Re-check them against the sealed Windows handoff. The only consumers of `SourceMediaMessages.cs` are `LinuxSourceMedia.cs` and the `ClientSession` reply forwarding.

Tests are written but NOT run: native CTest `peel-linux-audio-sink` with substituted non-device sinks (`identity`/`fakesink`, test-only injection) plus a process-local rank demotion of every audio sink, which proves the real autoaudiosink fake fallback is rejected, 23 fake managed receiver checks appended to `tests/` and 2 source guards in `tests-ui/`. They prove no audible playback, latency, GUI or device behavior. Runtime needs an autoaudiosink-selectable sink such as pulsesink through pipewire-pulse, or alsasink. Without one, Listen honestly shows unavailable and video is unchanged. Nothing in this delta has been compiled or run.
